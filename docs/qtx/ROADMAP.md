# QTx roadmap

| Phase | Goal | PASS condition |
| --- | --- | --- |
| P00 — Fork, Baseline & Project Contract | Preserve upstream and establish durable context. | Upstream history/remotes/baseline recorded; all styles and architecture inventoried; reasonable checks executed with limitations classified; contract and handoff committed; clean tree; fork pushed when authentication permits. A non-green baseline remains explicitly PARTIAL. |
| P01 — Upstream Full Parity | Understand and reproduce the full upstream production workflow. | All 11 baseline style families and A/B routing, approval, audio/captions, rendering and recovery verified with appropriate evidence; local blockers resolved and provider-dependent gaps explicitly closed with authorized work before claiming full parity. |
| P02 — QTx Series Production Workflow | Add filesystem Series/Video organization and approved asset reuse. | A series can resume across sessions using explicit project state, approvals and shared assets without altering upstream behavior. |
| P03 — Unity Renderer MVP | Add the smallest useful Unity rendering route. | One approved production renders through Unity and FFmpeg with reproducible inputs and preserved assets/audio. |
| P04 — QTx Animation Engine | Develop reusable story-driven animation capabilities. | Agreed representative motions and scene continuity pass visual review without breaking established production contracts. |
| P05 — End-to-End QTx Production MVP | Connect the approved production workflow end to end. | Topic through script/preview approval to final delivery works repeatably, including interruption recovery and approved asset reuse. |

These are large phases, not authorization to start them. No QTx feature implementation in P00.
